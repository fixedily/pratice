# v0 页面原型提示词（工业故障诊断系统）

本文档提供一组可直接粘贴到 [v0](https://v0.dev/) 的页面实现提示词，基于当前项目已有信息整理，覆盖：
- 业务主链路页面（首页、任务、案例、知识库）
- 运维页面（登录、仪表盘、工单详情）
- 统一视觉风格（深色、Linear 风格）

---

## 1. 使用方式

建议每次在 v0 新建一个页面时，按以下顺序输入提示词：
1. 先输入「全局风格提示词」
2. 再输入对应页面的「页面提示词」
3. 如果效果不理想，使用文档末尾的「迭代增强提示词」

---

## 2. 全局风格提示词（先发）

```text
请为一个工业故障诊断 SaaS 设计 Next.js + React + Tailwind 页面原型，风格参考 Linear（深色、高对比、精致边框、低饱和配色）。

视觉规则：
- 深色主背景：#08090a，面板背景：#0f1011，卡片背景使用 rgba(255,255,255,0.02~0.05)
- 文字层级：主文字 #f7f8f8，次级文字 #d0d6e0，弱化文字 #8a8f98
- 品牌强调色仅使用靛蓝紫：#5e6ad2 / #7170ff（只用于 CTA、激活状态、关键标签）
- 边框统一 1px solid rgba(255,255,255,0.08)，次级边框 rgba(255,255,255,0.05)
- 圆角体系：按钮/输入框 6px，卡片 8-12px，胶囊 9999px
- 阴影非常克制，以亮度层级和边框体现层次，不要夸张投影

版式与组件：
- 顶部导航 + 主内容区，最大宽度约 1200px
- 使用卡片、统计指标、表格、时间线、标签、空状态、加载骨架
- 页面需完整考虑：正常态、空态、加载态、错误态
- 全部文案使用中文，贴合工业故障检测场景

技术要求：
- 输出 React 组件代码，使用 TailwindCSS
- 组件拆分清晰，避免单一超大组件
- 保证响应式：移动端单列，桌面端多列
```

## 3. 页面提示词

### 3.1 产品官网/落地页（`/landing`）

```text
基于上面的全局风格，生成“工业故障智能诊断平台”产品落地页原型，目标用户是工厂运维工程师和生产管理者。

页面结构：
1) Hero 区：
   - 标题：工业故障诊断，从分钟级定位到闭环处理
   - 副标题：多智能体协同分析传感器数据，输出可执行诊断报告与工单建议
   - 两个按钮：立即体验（主按钮）、查看演示（次按钮）
   - 右侧放产品界面预览占位图（深色卡片）
2) 核心能力区（3~4 张卡片）：
   - 实时流式诊断（SSE）
   - 多模型切换（DeepSeek/OpenAI-compatible/Anthropic）
   - 传感器统计聚合（避免长上下文）
   - 工单闭环追踪
3) 场景价值区（2 列）：
   - 降低停机损失、提升排障效率、沉淀知识资产
4) 指标区：
   - 4 个 KPI（如平均定位时长、诊断命中率、工单闭环率、知识复用率）
5) CTA 区 + Footer

细节要求：
- 所有卡片 hover 时仅做轻微亮度变化
- 提供按钮、卡片、指标模块的可复用子组件
- 兼顾桌面和移动端排版
```

### 3.2 诊断任务页（`/tasks`）

```text
生成“诊断任务列表页”原型，面向运维工程师查看和筛选历史诊断任务。

页面结构：
1) 顶部操作栏：
   - 页面标题：诊断任务
   - 搜索框（按任务 ID/症状关键词）
   - 筛选器：状态、模型提供商、时间范围
   - 主按钮：新建诊断
2) 统计条：
   - 今日任务数、进行中、已完成、失败数（4 个指标卡）
3) 任务表格：
   - 列：任务ID、时间范围、症状描述、模型、状态、耗时、操作
   - 支持状态标签颜色区分（保持整体深色低饱和）
4) 分页区
5) 空状态：无数据时提示“创建首个诊断任务”

交互与状态：
- 提供加载骨架行
- 提供错误提示条（可重试）
- 行点击进入任务详情页 `/tasks/[taskId]`
```

### 3.3 任务详情与流式结果页（`/tasks/[taskId]`）

```text
生成“任务详情 + 流式诊断结果”页面原型，突出实时过程和最终报告。

页面采用左右布局：
- 左侧（约 35%）：任务元信息与参数
  - 时间范围、症状描述、模型配置、任务状态、创建时间
  - 控件：重新运行、导出报告
- 右侧（约 65%）：流式事件时间线 + 报告面板
  - 事件类型：connected、node_start、node_finish、report、error、done
  - 时间线按时间排序，支持自动滚动到最新事件
  - 最终报告区域支持代码块样式展示关键结论

补充区块：
- 关键传感器统计摘要卡片（均值/最小/最大）
- 推荐处理动作（3 条）

状态设计：
- 进行中：显示流动状态条
- 完成：显示“诊断完成”徽标
- 失败：显示错误信息与“重试”按钮
```

### 3.4 案例库列表页（`/cases`）

```text
生成“故障案例库列表页”原型，用于浏览历史沉淀案例。

页面结构：
1) 顶部：
   - 标题：故障案例库
   - 搜索框（设备/故障现象/根因）
   - 筛选：设备类型、故障等级、是否已验证
   - 按钮：新建案例
2) 案例卡片网格（桌面 3 列，平板 2 列，移动 1 列）
   - 卡片字段：案例标题、设备、故障标签、摘要、更新时间、验证状态
   - 点击进入 `/cases/[caseId]`
3) 右上角提供视图切换（卡片/表格）
4) 空状态与加载骨架

样式要求：
- 标签使用胶囊样式
- 验证状态用低饱和绿色点标记
- 卡片边框轻微发亮，保持克制
```

### 3.5 案例详情页（`/cases/[caseId]`）

```text
生成“故障案例详情页”原型，强调可复盘和可执行。

页面结构：
1) 头部信息：
   - 案例标题、设备信息、故障等级、更新时间、负责人
2) 主体三段：
   - 故障现象（Symptoms）
   - 根因分析（Root Cause）
   - 处理方案（Action Plan）
3) 证据区：
   - 关键传感器指标表 + 趋势图占位
4) 关联知识：
   - 关联文档、关联历史任务、相似案例
5) 底部操作：
   - 编辑案例、导出 PDF、标记已验证

交互要求：
- 左侧目录锚点，支持快速跳转各章节
- 提供“复制处理步骤”按钮
```

```text
页面结构：
```

### 3.7 运维登录页（`/maintenance/login`）

```text
生成“运维后台登录页”原型，风格与主系统一致但更聚焦安全感。

页面结构：
- 居中登录卡片（账号、密码、二次验证码）
- 记住我、忘记密码
- 登录按钮（主色）
- 次级入口：返回主站
- 卡片下方显示系统状态提示（例如 API 连通、数据库状态）

视觉要求：
- 背景可以有极弱渐变或噪点纹理
- 输入框 focus 态清晰
- 错误提示（账号或密码错误）需要醒目但不刺眼
```

### 3.8 运维仪表盘（`/maintenance/dashboard`）

```text
生成“运维仪表盘”页面原型，用于监控系统健康状态。

页面结构：
1) 顶部概览卡：
   - API 状态、数据库状态、队列堆积、活跃会话

   - 左：最近告警列表（级别、来源、时间、状态）

交互与状态：
```

## 4. 迭代增强提示词（可选）

当你对 v0 首版结果不满意时，可追加以下提示词进行二次优化：

```text
请在不改变信息架构的前提下，继续优化这个页面：
1) 提升“工业监控”场景识别度：增加传感器、趋势、告警相关视觉暗示
2) 提升组件一致性：统一按钮、标签、表格、卡片的状态样式
3) 增加真实感：补充空状态、加载骨架、错误提示、长文本截断
4) 优化响应式：明确 mobile / tablet / desktop 的布局切换
5) 代码可维护：抽离可复用组件，减少重复样式
```
