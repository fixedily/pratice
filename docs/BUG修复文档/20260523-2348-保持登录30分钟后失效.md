# BUG 修复报告

## 基本信息
- 日期：2026-05-23
- 报告人：Codex
- 模块/功能：检修域登录 / 7 天内保持登录 / 本地开发启动脚本
- 严重级别（低/中/高）：高
- 影响范围：本地开发环境下使用“7 天内保持登录”的用户
- 严重级别依据（是否阻断/可绕过/影响用户数）：30 分钟后 access token 过期会被推回登录页，直接中断正在进行的后台操作；可通过使用同一 hostname 临时绕过。

## 问题描述
- 期望结果：勾选“7 天内保持登录”后，access token 30 分钟过期时应通过 HttpOnly refresh cookie 自动换新，不应跳回登录页。
- 实际结果：用户约 30 分钟后自动回退到登录页面。

## 复现步骤（必须可复现）
1) 使用脚本启动本地前后端，后端 API 地址为 `http://127.0.0.1:18000`。
2) 在浏览器通过 `http://localhost:3000/login` 登录，并勾选“7 天内保持登录”。
3) 等待 access token 到期，或等待页面发起需要检修域鉴权的请求。
4) 前端调用 refresh 接口时没有携带 refresh cookie，最终触发“登录已失效”并跳回登录页。

## 复现环境
- 设备/系统：Windows 本地开发
- 应用版本/配置：Next.js 前端 + FastAPI 后端，前端 `localhost:3000`，API `127.0.0.1:18000`
- 相关依赖或外部条件：浏览器 SameSite Cookie 策略；refresh token 使用 HttpOnly Cookie，`SameSite=Lax`

## 定位过程
- 关键线索：30 分钟正好对应 `ACCESS_TOKEN_EXPIRE_MINUTES=30`；后端已正确设置 7 天 refresh cookie。
- 排查路径：
  - 检查登录页确认 `remember_me` 已提交。
  - 检查后端 `set_refresh_cookie` 确认勾选时 `Max-Age=604800`。
  - 检查前端全局过期事件，确认 refresh 失败后会跳转 `/login`。
  - 对比本地访问 hostname，发现前端可能为 `localhost`，API 为 `127.0.0.1`。
- 根因说明：`localhost` 与 `127.0.0.1` 对浏览器 Cookie 策略不是同一个站点。refresh cookie 设置为 `SameSite=Lax`，跨站 fetch 不会携带该 Cookie；因此 30 分钟后 access token 过期，refresh 请求拿不到 cookie，前端被判定登录失效。

## 修复方案
- 修改点说明：
  - `getApiBase()` 在浏览器端检测本地 loopback hostname 不一致时，自动把 API hostname 对齐为当前页面 hostname。
  - `scripts/start-dev.ps1` 改为默认使用 `localhost` 启动后端和前端，并显式传入 Next dev 的 hostname/port。
  - 勾选“7 天内保持登录”时同步记录前端记住偏好，access token 存入 `localStorage`；后续 refresh 成功后根据后端 `remember_me` 继续沿用该偏好。
  - 登录页初始化时读取记住偏好，避免跳回登录页后复选框默认变成未勾选造成误操作。
- 影响评估：仅影响本地 `localhost`/`127.0.0.1` 开发访问；生产和内网穿透地址不受该自动对齐逻辑影响。
- 风险点：如果用户手动配置了只监听某一个 loopback host 的后端，同时用另一个 hostname 打开前端，仍需通过启动脚本或 `.env.local` 保持一致。
- 回滚方案：回退 `frontend/shared/lib/http.ts` 的 `getApiBase()` hostname 对齐逻辑，以及 `scripts/start-dev.ps1` 的 host/Next dev 参数改动。

  - 前端 token 存储支持 remember 偏好，refresh 后保持同样存储策略。

## 验证步骤（手动，逐步）
1) 关闭旧的前端和后端进程。
2) 清理旧登录态：删除浏览器中 `localhost` 和 `127.0.0.1` 下的 `faultdiag_refresh_token` Cookie，并清理站点 localStorage/sessionStorage。
3) 在项目根目录执行 `.\scripts\start-dev.ps1`。
4) 使用脚本输出的 `http://localhost:3000` 打开登录页。
5) 勾选“7 天内保持登录”并登录。
6) 打开浏览器开发者工具，确认后端登录响应设置了 `faultdiag_refresh_token` Cookie，且带有 `Max-Age=604800`。
7) 等待 30 分钟，或临时把 access token 清掉后刷新后台页面。
8) 观察页面应继续保持登录；Network 中 `/api/auth/refresh` 应返回 200，并重新拿到 access token。
